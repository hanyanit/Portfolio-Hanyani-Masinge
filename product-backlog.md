# Product Backlog — Opportunity Connect

## 1. Introduction

The Product Backlog for Opportunity Connect contains the features and development tasks required to build and improve the application. The backlog was created from the identified user stories and was used to organize development work according to priority and value to the users.

Opportunity Connect is a platform designed to help students discover bursaries and other opportunities that they may qualify for. The application uses an Angular frontend and a Python backend.

The Product Backlog follows Agile principles by allowing development work to be prioritized, reviewed and adjusted as the needs of the users and the project changed.

## 3. Backlog Prioritisation

The backlog was prioritised according to the value that each feature provides to the main users of Opportunity Connect.

### High-Priority Features

The high-priority features focus on the main purpose of the application: allowing students to access and discover relevant bursaries and opportunities.

These features include:

- Creating an account
- Logging in
- Viewing opportunities
- Searching for opportunities
- Filtering opportunities
- Viewing opportunity details
- Finding relevant opportunities

These features were considered important because they directly support the main user journey of discovering opportunities.

### Medium-Priority Features

The medium-priority features support the overall usability and administration of the platform.

These include:

- Managing user information
- Managing opportunity information
- Supporting different screen sizes and devices

These features are important to the overall quality of the application but can be developed alongside or after the core opportunity-discovery functionality.

## 4. Product Backlog Refinement

The Product Backlog can change throughout the development process. New requirements can be added, existing requirements can be changed, and priorities can be adjusted based on user feedback and project needs.

For Opportunity Connect, backlog refinement helped break larger requirements into smaller pieces of work that could be planned and implemented during development.

For example, the requirement to allow students to find opportunities can be divided into smaller tasks such as:

1. Create the opportunity data structure.
2. Display available opportunities.
3. Implement the search functionality.
4. Implement filtering.
5. Connect the Angular frontend to the Python backend.
6. Test the results returned to the user.
7. Improve the user interface.

This makes the development process more manageable and allows progress to be tracked.

---

## 5. Relationship Between the Product Backlog and User Stories

The Product Backlog was developed from the User Stories identified for Opportunity Connect.

The User Stories describe **what the user needs**, while the Product Backlog organizes those needs according to priority and estimated development effort.

For example:

**User Story:**

> As a student, I want to search for opportunities so that I can quickly find relevant opportunities.

This user story can result in several development tasks:

- Create a search field.
- Connect the search field to the opportunity data.
- Implement search functionality in the backend.
- Display matching opportunities.
- Test different search terms.
- Handle cases where no results are found.

This demonstrates how Agile development breaks larger requirements into manageable pieces of work.

## 7. Reflection

Creating the Product Backlog helped me understand how Agile development can be used to organise a software project. Instead of attempting to develop the entire Opportunity Connect application at once, the project requirements were divided into smaller user-focused items.

Prioritising the backlog helped me identify which features were most important to the main purpose of the application. Features related to finding and accessing bursaries and opportunities were given higher priority because they provide the main value to students.

The Product Backlog also helped me understand that software requirements can change during development. Agile allows the team to review priorities and adjust the backlog when new requirements, feedback or challenges are identified.

One of the main lessons I learned was that a backlog is not simply a list of tasks. It is a way of connecting development work to user needs and business value. This helped me think more carefully about why a feature should be developed and what benefit it provides to the users.

Overall, creating and managing the Product Backlog improved my understanding of Agile planning, prioritisation and incremental software development.
