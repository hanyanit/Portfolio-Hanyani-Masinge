# Agile Logbook — Opportunity Connect

## 1. Introduction

The Agile Logbook documents my development journey while working on Opportunity Connect. It records the activities, progress, challenges, decisions and lessons learned throughout the development process.

The purpose of the logbook is to provide evidence of how Agile principles were applied during the development of the project.

Opportunity Connect was developed as a platform to help students discover bursaries and other opportunities that they may qualify for. The project used Angular for the frontend and Python for the backend.

---

# 2. Agile Development Log

## Entry 1 — Project Planning

### Activity

The first stage of the project involved understanding the purpose of Opportunity Connect and identifying the problem that the application was intended to solve.

The main objective was to create a platform that could help students discover relevant bursaries and opportunities in one place.

### Work Completed

- Identified the purpose of the application.
- Identified the target users.
- Considered the main user needs.
- Discussed the functionality required by the application.
- Started planning the application structure.

### Agile Practice

This stage involved Agile planning because the project requirements were considered from the perspective of the users and their needs.

### Reflection

At the beginning of the project, I learned that understanding the problem before starting development is important. It helped me focus on creating functionality that provides value to students rather than developing features without a clear purpose.

---

# Entry 2 — Creating User Stories

### Activity

After identifying the main requirements, I converted user requirements into User Stories.

The User Stories described the functionality from the perspective of the people using Opportunity Connect.

### Work Completed

Examples included:

- Creating a student account.
- Logging into the application.
- Viewing opportunities.
- Searching for opportunities.
- Filtering opportunities.
- Viewing opportunity details.

### Agile Practice

User Stories were used to keep the development process focused on user needs.

### Reflection

Creating User Stories helped me understand requirements from the user's perspective. Instead of only thinking about the technical implementation, I had to consider what the user wanted to accomplish and why the functionality was useful.

This also made it easier to break larger requirements into smaller pieces of work.

---

# Entry 3 — Product Backlog

### Activity

The User Stories were organised into a Product Backlog.

The backlog was used to identify the features required for the application and prioritise them according to their importance.

### Work Completed

The Product Backlog included features such as:

- User registration.
- User login.
- Viewing opportunities.
- Searching for opportunities.
- Filtering opportunities.
- Viewing opportunity details.
- Finding relevant opportunities.

### Agile Practice

Backlog prioritisation was used to determine which features should receive more attention during development.

### Reflection

Creating the Product Backlog helped me understand the importance of prioritisation in software development. Not every feature has the same level of importance, so development should focus first on functionality that provides the most value to the users.

---

# Entry 4 — Sprint Planning

### Activity

Selected Product Backlog items were broken down into smaller tasks for development.

The Sprint Backlog was used to identify the specific work that needed to be completed during the development cycle.

### Work Completed

Tasks included:

- Creating frontend interfaces.
- Connecting frontend components to the backend.
- Implementing functionality.
- Testing features.
- Fixing errors.
- Improving the user interface.

### Agile Practice

Sprint planning helped divide larger requirements into smaller and more manageable tasks.

### Reflection

Sprint planning taught me that software development becomes easier to manage when large requirements are divided into smaller tasks.

It also helped me understand that sprint planning needs to be realistic. Development time, technical challenges and the complexity of a feature need to be considered when deciding how much work can be completed.

---

# Entry 5 — Frontend Development

### Activity

The Angular frontend was developed to provide the user interface for Opportunity Connect.

### Work Completed

Frontend development included creating and connecting the different interfaces required by the application.

The frontend was responsible for presenting information to users and allowing them to interact with the application.

### Agile Practice

Frontend functionality was developed incrementally rather than attempting to build the entire application at once.

### Reflection

Working on the frontend helped me understand the importance of developing functionality in smaller increments. It also showed me how changes to requirements can affect different parts of an application.

I learned that creating a user interface requires consideration of both functionality and usability.

---

# Entry 6 — Backend Development

### Activity

The Python backend was developed to support the application's functionality and data processing.

### Work Completed

Backend development included creating the functionality required to support communication between the frontend and backend.

### Agile Practice

Backend functionality was developed alongside the requirements identified in the backlog.

### Reflection

Working on the backend helped me better understand the relationship between the frontend and backend of a web application.

I learned that successful frontend functionality often depends on reliable backend communication and that both sides need to be tested together.

---

# Entry 7 — Frontend and Backend Integration

### Activity

The Angular frontend was connected to the Python backend.

### Work Completed

The integration process involved:

- Connecting frontend requests to backend functionality.
- Sending information between the frontend and backend.
- Testing responses.
- Identifying integration issues.
- Fixing errors.

### Agile Practice

Integration and testing were performed as part of the development process instead of leaving all integration work until the end.

### Reflection

This stage taught me the importance of testing the interaction between different parts of a system.

A feature may work correctly on the frontend or backend individually but still have problems when the two systems communicate. This helped me understand why continuous testing and integration are important in Agile development.

---

# Entry 8 — Testing and Bug Fixing

### Activity

Testing was performed throughout development to identify problems and verify that functionality worked as expected.

### Work Completed

Testing included:

- Testing application functionality.
- Identifying errors.
- Fixing implementation problems.
- Testing frontend and backend communication.
- Checking user interactions.

### Agile Practice

Testing was treated as part of the development process rather than only being performed at the end of the project.

### Reflection

Testing helped me understand that finding errors early can make software development easier. Fixing problems as they were identified reduced the risk of allowing issues to affect other parts of the application.

I also learned that testing should be considered throughout development because changes to one feature can sometimes affect another feature.

---

# Entry 9 — Challenges and Problem Solving

### Challenge

One of the challenges during development was dealing with technical issues that occurred while implementing and integrating different parts of the application.

### Response

When problems occurred, I investigated the cause of the issue, tested possible solutions and made changes to the implementation.

### Agile Practice

The Agile approach supported this process because development work could be reviewed and adjusted when problems were identified.

### Reflection

The challenges I experienced taught me that software development is an iterative process. Not every implementation works correctly on the first attempt.

I learned to approach problems systematically by identifying the issue, investigating possible causes, testing solutions and then verifying whether the solution worked.

# 4. Overall Reflection

Working on Opportunity Connect helped me understand how Agile principles can be applied to a real software development project.

Before working with Agile development practices, it was easy to think of software development as simply writing code until the application was complete. The Agile process showed me that successful software development also requires planning, prioritisation, communication, testing, feedback and continuous improvement.

Creating User Stories helped me focus on what users needed. The Product Backlog helped me prioritise those requirements, while the Sprint Backlog helped break selected requirements into smaller development tasks.

I also learned that development does not always follow the original plan exactly. Technical problems, changes in requirements and new ideas can require adjustments. Agile provides flexibility because the backlog and development priorities can be reviewed and changed.

One of the most valuable lessons I learned was the importance of incremental development. Developing and testing smaller pieces of functionality makes it easier to identify problems and make improvements.

The project also improved my technical skills because I worked with Angular on the frontend and Python on the backend. More importantly, it helped me understand how technical development activities connect to project planning and user requirements.

Overall, the Agile process helped me become more organised and more focused on delivering value to users. It also improved my understanding of how professional software development teams can manage complex projects.

---

# 5. Key Lessons Learned

Through the development of Opportunity Connect, I learned that:

1. User requirements should guide software development.
2. Large requirements can be broken into smaller User Stories and tasks.
3. Backlogs help teams prioritise development work.
4. Sprint planning helps create a manageable development focus.
5. Testing should happen throughout development.
6. Technical problems require investigation and iterative problem solving.
7. Requirements can change during software development.
8. Working software provides useful evidence of progress.
9. Version control helps track development work.
10. Reflection helps identify areas for future improvement.

---

# 6. Conclusion

The Agile Logbook provides evidence of my development journey while working on Opportunity Connect.

By applying Agile practices such as User Stories, Product Backlog management, Sprint planning, incremental development, testing and reflection, I was able to organise the development process and focus on creating value for the users.

The project helped me connect Agile theory with practical software development and gave me a better understanding of how Agile methodologies can be used to manage a real-world software project.
